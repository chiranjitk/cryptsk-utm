     1→# Page Map — Single-Route SPA Views
     2→
     3→> **TL;DR:** The console is a single Next.js route (`/` → `src/app/page.tsx`) that renders
     4→> `AppShell`. All 28 screens are client-side hash views (`#/dashboard`, `#/firewall/rules`,
     5→> …) resolved from a `viewRegistry` — this is a HARD sandbox rule (ADR-006). This document
     6→> reproduces the LOCKED view map, defines the shell layout and sidebar tree, and gives a
     7→> compact blueprint (layout, components, hooks, realtime, actions) for every view.

    17→## 1. Routing Model
    18→
    19→- **Why hashes:** the sandbox exposes exactly one user-visible route (`/`). ADR-006
    20→  (DECISIONS.md) locks the decision: one Next route, `AppShell` parses
    21→  `window.location.hash`, and renders the matching view from
    22→  `src/components/shell/view-registry.ts`. Creating any other Next.js route is a bug
    23→  (PROJECT_MEMORY §11.1).
    24→- **Registry entry:** `{ path: "#/firewall/rules", group: "Firewall", label: "Rules",
    25→  icon: LucideIcon, component: DynamicComponent, order }`. Sidebar and breadcrumbs are
    26→  generated from the registry, never hand-written per view.
    27→- **Hash syntax:** `#/` + group + `/` + view. Tabbed views append the tab id as a third
    28→  segment for deep links (`#/firewall/objects/services`, `#/dns-dhcp/dns/records`);
    29→  the LOCKED two-segment paths from PROJECT_MEMORY §8 always resolve to the first tab.
    30→  Filter deep links use hash query params: `#/ips/events?severity=critical`.
    31→- **Deep-linking / back / forward / refresh:** all work for free via `hashchange` — the
    32→  shell listens on the event, parses the hash, and swaps the view (per-view code splitting
    33→  via `next/dynamic` mitigates the single-bundle trade-off of ADR-006).
    34→- **Auth gate:** when unauthenticated, `AuthGate` renders the `#/login` view **in place of
    35→  the whole shell** (no sidebar/topbar leak). After successful login the user lands on the
    36→  originally requested hash, or `#/dashboard` when the request was bare `/`.
    37→- **Session expiry:** any `401` from the fetch wrapper clears the app store and points the
    38→  hash to `#/login` (see STATE_AND_DATA_FLOW §3).

    40→## 2. Shell Layout
    41→
    42→```mermaid
    43→flowchart TB
    44→    subgraph Shell["AppShell (src/components/shell/)"]
    45→        TOP["Topbar: menu button (mobile) · breadcrumbs · notifications bell<br/>· theme toggle · user menu (avatar dropdown)"]
    46→        subgraph BODY["flex row"]
    47→            NAV["Sidebar: CRYPTSK wordmark + ShieldCheck<br/>11 nav groups from viewRegistry<br/>collapse toggle (icon rail)"]
    48→            MAIN["Main content: ViewRenderer → active view<br/>scrollable, p-4/p-6, max-w constraints"]
    49→        end
    50→        FOOT["Footer slot: sticky footer (min-h-screen flex flex-col + mt-auto)<br/>only on login-style surfaces, never overlays content"]
    51→    end
    52→    GATE["AuthGate: no session → renders #/login instead of this shell"]
    53→    GATE --> Shell
    54→```
    55→
    56→- **Sidebar** (built on `ui/sidebar.tsx`): collapsible — full labels on lg+, icon rail on
    57→  md, hidden into a `Sheet` on mobile. Active item: emerald primary treatment; group
    58→  headers are muted `text-xs` labels. Collapse state persists in `ui-store`.
    59→- **Topbar:** mobile menu button (opens the sidebar `Sheet`), breadcrumbs (tabbed views),
    60→  notifications bell (`Popover` listing notifications; unread count badge;
    61→  `alerts:new` pushes into it), theme toggle (`Sun`/`Moon` via next-themes), user menu
    62→  (`DropdownMenu`: username + role, "Logout" → `POST /api/v1/auth/logout` → `#/login`).
    63→- **Notifications data:** `GET /api/v1/notifications?unread=` +
    64→  `POST /api/v1/notifications/{id}/read` (mark read on open).
    65→- **Footer:** only the login view carries a footer (sticky per §11.12); app views fill
    66→  the viewport and scroll the main region.

   111→## 4. Per-View Blueprints
   112→
   113→Conventions: "Components" lists shared patterns from [UI_DESIGN_SYSTEM §5](./UI_DESIGN_SYSTEM.md#5-component-patterns-canonical-shared-registry)
   114→plus `ui/*` primitives; "Data" names the hooks (`src/hooks/`, TanStack Query) and the
   115→LOCKED endpoints they call; "Realtime" lists PROJECT_MEMORY §7.3 events the view
   116→subscribes to (`config:updated` is handled globally — see STATE_AND_DATA_FLOW §4 — and is
   117→listed only where it drives the whole view). Module specs in `../06-MODULES/` own the
   118→detailed behavior; blueprints here stay layout-level.

   122→### `#/login`
   123→- **Purpose:** authenticate and obtain the `cryptsk_token` cookie.
   124→- **Layout:** centered card on `--background`; CRYPTSK wordmark + ShieldCheck; username +
   125→  password fields; sign-in button; inline error for wrong credentials; **sticky footer**
   126→  (console/legal links) via `min-h-screen flex flex-col` + `mt-auto`.
   127→- **Components:** Card, Form, Input, Button, Alert; footer slot.
   128→- **Data:** `useLogin()` → `POST /api/v1/auth/login`; session bootstrap `GET /api/v1/auth/me`.
   129→- **Realtime:** none (socket connects after login).
   130→- **Actions:** sign in; redirect to originally requested hash or `#/dashboard`.

   132→### `#/dashboard`
   133→- **Purpose:** 30-second health answer: traffic, sessions, threats, WAN/VPN, system.
   134→- **Layout:**
   135→```
   136→┌ health strip: StatusBadge healthy|degraded|critical · uptime · quick actions ┐
   137→┌ MetricCard throughput ┬ MetricCard sessions ┬ alerts 24h ┬ notifications ───┤
   138→┌ throughput area chart (rx/tx, Live|1h|24h) ────┬ top apps donut ─────────────┤
   139→┌ top talkers table ─────────────────────────────┬ threat feed (max-h-96) ─────┤
   140→┌ WAN strip badges ┬ VPN tunnel list ┬ CPU/RAM/disk Gauges · temp · services ───┘
   141→```
   142→- **Components:** PageScaffold, MetricCard, Sparkline, Gauge, StatusBadge, DataTable (talkers), EmptyState, ChartContainer (Area/Pie).
   143→- **Data:** `useDashboardSummary()` → `GET /api/v1/dashboard/summary`; `useSystemStatus()` → `GET /api/v1/system/status`; range switch → `GET /api/v1/logs/stats?range=1h|24h`.
   144→- **Realtime:** `metrics:tick` (ring buffer → cards + live chart), `wan:status` (strip), `alerts:new` (feed + badge), `sessions:update` (debounced summary refetch).
   145→- **Actions:** range switch; "Create backup" → `POST /api/v1/system/backups`; "Restart service" (simulated stub per M01 §5); deep links to WAN/VPN/IPS views. Details: [M01](../06-MODULES/M01-DASHBOARD.md).

   377→## 5. Navigation Behaviors
   378→
   379→- **Unknown hash:** any hash that misses the registry redirects to `#/dashboard` and fires
   380→  one `toast.info("Unknown page — redirected to dashboard")`. Never render a blank main.
   381→- **Per-group default child:** the first item of each group in §3 is its default
   382→  (`#/network` → `#/network/interfaces`, `#/logs` → `#/logs/firewall`, …). Group headers
   383→  in the sidebar navigate to their default child.
   384→- **Last-visited memory:** `ui-store` (zustand `persist`) keeps `lastViews: Record<group,
   385→  path>`; a bare `#/group` or app relaunch with bare `#/` restores the group's last
   386→  visited child, else its default. `activeView`, `sidebarCollapsed` persist the same way.
   387→- **Breadcrumbs:** tabbed views render `Breadcrumb` in the topbar:
   388→  `Firewall / Objects / Address` (group / view / tab). Non-tabbed views show
   389→  `Group / View`. Breadcrumbs are links built from the registry — clicking the group goes
   390→  to its default child.
   391→- **Scroll reset:** on hash change the main region scrolls to top; focus moves to the view
   392→  `h1` (`tabIndex={-1}`) for keyboard/screen-reader orientation.
