     1→     1→# Page Map — Single-Route SPA Views
     2→     2→

     4→     4→> `AppShell`. All 29 screens are client-side hash views (`#/dashboard`, `#/firewall/rules`,

    18→    18→## 1. Routing Model
    19→    19→
    20→    20→- **Why hashes:** the sandbox exposes exactly one user-visible route (`/`). ADR-006
    21→    21→  (DECISIONS.md) locks the decision: one Next route, `AppShell` parses
    22→    22→  `window.location.hash`, and renders the matching view from
    23→    23→  `src/components/shell/view-registry.ts`. Creating any other Next.js route is a bug
    24→    24→  (PROJECT_MEMORY §11.1).
    25→    25→- **Registry entry:** `{ path: "#/firewall/rules", group: "Firewall", label: "Rules",
    26→    26→  icon: LucideIcon, component: DynamicComponent, order }`. Sidebar and breadcrumbs are
    27→    27→  generated from the registry, never hand-written per view.
    28→    28→- **Hash syntax:** `#/` + group + `/` + view. Tabbed views append the tab id as a third
    29→    29→  segment for deep links (`#/firewall/objects/services`, `#/dns-dhcp/dns/records`);
    30→    30→  the LOCKED two-segment paths from PROJECT_MEMORY §8 always resolve to the first tab.
    31→    31→  Filter deep links use hash query params: `#/ips/events?severity=critical`.
    32→    32→- **Deep-linking / back / forward / refresh:** all work for free via `hashchange` — the
    33→    33→  shell listens on the event, parses the hash, and swaps the view (per-view code splitting
    34→    34→  via `next/dynamic` mitigates the single-bundle trade-off of ADR-006).
    35→    35→- **Auth gate:** when unauthenticated, `AuthGate` renders the `#/login` view **in place of
    36→    36→  the whole shell** (no sidebar/topbar leak). After successful login the user lands on the
    37→    37→  originally requested hash, or `#/dashboard` when the request was bare `/`. The same
    38→    38→  gate pattern hosts the **setup gate**: while `setup.completed` is false, `#/setup`
    39→    39→  renders instead of the shell (PROJECT_MEMORY §8, view 29).
    40→    40→- **Session expiry:** any `401` from the fetch wrapper clears the app store and points the
    41→    41→  hash to `#/login` (see STATE_AND_DATA_FLOW §3).

    43→    43→## 2. Shell Layout
    44→    44→
    45→    45→```mermaid
    46→    46→flowchart TB
    47→    47→    subgraph Shell["AppShell (src/components/shell/)"]
    48→    48→        TOP["Topbar: menu button (mobile) · breadcrumbs · notifications bell<br/>· theme toggle · user menu (avatar dropdown)"]
    49→    49→        subgraph BODY["flex row"]
    50→    50→            NAV["Sidebar: CRYPTSK wordmark + ShieldCheck<br/>11 nav groups from viewRegistry<br/>collapse toggle (icon rail)"]
    51→    51→            MAIN["Main content: ViewRenderer → active view<br/>scrollable, p-4/p-6, max-w constraints"]
    52→    52→        end
    53→    53→        FOOT["Footer slot: sticky footer (min-h-screen flex flex-col + mt-auto)<br/>only on login-style surfaces, never overlays content"]
    54→    54→    end
    55→    55→    GATE["AuthGate: no session → renders #/login instead of this shell"]
    56→    56→    GATE --> Shell
    57→    57→```
    58→    58→
    59→    59→- **Sidebar** (built on `ui/sidebar.tsx`): collapsible — full labels on lg+, icon rail on
    60→    60→  md, hidden into a `Sheet` on mobile. Active item: emerald primary treatment; group
    61→    61→  headers are muted `text-xs` labels. Collapse state persists in `ui-store`.
    62→    62→- **Topbar:** mobile menu button (opens the sidebar `Sheet`), breadcrumbs (tabbed views),
    63→    63→  notifications bell (`Popover` listing notifications; unread count badge;
    64→    64→  `alerts:new` pushes into it), theme toggle (`Sun`/`Moon` via next-themes), user menu
    65→    65→  (`DropdownMenu`: username + role, "Logout" → `POST /api/v1/auth/logout` → `#/login`).
    66→    66→- **Notifications data:** `GET /api/v1/notifications?unread=` +
    67→    67→  `POST /api/v1/notifications/{id}/read` (mark read on open).
    68→    68→- **Footer:** only the login view carries a footer (sticky per §11.12); app views fill
    69→    69→  the viewport and scroll the main region.

   128→   128→### `#/login`
   129→   129→- **Purpose:** authenticate and obtain the `cryptsk_token` cookie.

   131→   131→  password fields; sign-in button; inline error for wrong credentials; **sticky footer**

   138→   138→### `#/dashboard`
   139→   139→- **Purpose:** 30-second health answer: traffic, sessions, threats, WAN/VPN, system.
   140→   140→- **Layout:**
   141→   141→```
   142→   142→┌ health strip: StatusBadge healthy|degraded|critical · uptime · quick actions ┐
   143→   143→┌ MetricCard throughput ┬ MetricCard sessions ┬ alerts 24h ┬ notifications ───┤
   144→   144→┌ throughput area chart (rx/tx, Live|1h|24h) ────┬ top apps donut ─────────────┤
   145→   145→┌ top talkers table ─────────────────────────────┬ threat feed (max-h-96) ─────┤
   146→   146→┌ WAN strip badges ┬ VPN tunnel list ┬ CPU/RAM/disk Gauges · temp · services ───┘
   147→   147→```
   148→   148→- **Components:** PageScaffold, MetricCard, Sparkline, Gauge, StatusBadge, DataTable (talkers), EmptyState, ChartContainer (Area/Pie).
   149→   149→- **Data:** `useDashboardSummary()` → `GET /api/v1/dashboard/summary`; `useSystemStatus()` → `GET /api/v1/system/status`; range switch → `GET /api/v1/logs/stats?range=1h|24h`.
   150→   150→- **Realtime:** `metrics:tick` (ring buffer → cards + live chart), `wan:status` (strip), `alerts:new` (feed + badge), `sessions:update` (debounced summary refetch).
   151→   151→- **Actions:** range switch; "Create backup" → `POST /api/v1/system/backups`; "Restart service" → `POST /api/v1/system/services/{name}/restart` (menu of running services from `/system/status`; audited, simulated — M01 §4); deep links to WAN/VPN/IPS views. Details: [M01](../06-MODULES/M01-DASHBOARD.md).

   153→   153→### `#/network/interfaces` — 4 tabs: Interfaces | LLDP Neighbors | MAC Table | Mirroring (SPAN)
   154→   154→- **Purpose:** manage physical/VLAN/bridge/bond/loopback/GRE/IPIP interfaces with live stats, plus the switching extras (LLDP discovery, FDB view, SPAN sessions).
   155→   155→- **Layout (tab 1):** full-width table (name, type/role chips, L2/L3 mode chip, addresses, StatusBadge link state, rx/tx Sparkline) + detail `Sheet` (config, counters, errors/drops). Tab 2 LLDP Neighbors: derived neighbor table (auto-refresh 10 s, not persisted). Tab 3 MAC Table: derived FDB view with iface/VLAN filters. Tab 4 Mirroring: `PortMirror` CRUD table (one active mirror per source iface).
   156→   156→- **Components:** PageScaffold, Tabs, DataTable, StatusBadge, Sparkline, Sheet, ConfirmDialog, FormSection dialogs.
   157→   157→- **Data:** `useInterfaces()` → `GET/POST /api/v1/interfaces`; `GET/PUT/DELETE /api/v1/interfaces/{id}`; `useInterfaceStats(id)` → `GET /api/v1/interfaces/{id}/stats`; `useLldpNeighbors()` → `GET /api/v1/network/lldp-neighbors`; `useMacTable()` → `GET /api/v1/network/mac-table?iface=&vlan=&q=`; `usePortMirrors()` → `GET/POST /api/v1/network/port-mirrors` + `PUT/DELETE /{id}`.
   158→   158→- **Realtime:** `metrics:tick` (per-iface `rxKbps`/`txKbps` sparklines); LLDP/MAC tabs are engine-derived (10 s auto-refresh, no socket event — flagged in REVIEW-4A).
   159→   159→- **Actions:** create (vlan/bridge/bond/gre/ipip/loopback), edit (incl. `mode l2|l3`, `wanType`, `config.lldp`, bridge `stpMode`/`igmpSnooping`), delete (non-physical only — disabled with Tooltip otherwise); mirror CRUD. Details: [M02](../06-MODULES/M02-NETWORK.md).
