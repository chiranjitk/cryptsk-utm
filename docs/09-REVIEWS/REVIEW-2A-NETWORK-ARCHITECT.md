## (a) Executive summary

The doc set is unusually strong for pre-code documentation: the packet pipeline order (NIC → XDP → nftables/conntrack/NAT → TPROXY branch → nDPI → Suricata inline → tc egress) matches the spec in every document, config-change flow (draft → DB tx → generator → atomic apply → rollback) is correct, and the console/appliance split is consistently drawn. The two most consequential network-domain problems were (1) **Suricata inline deployment described as AF_PACKET while every diagram places Suricata inside the routed host path** — technically impossible (AF_PACKET inline is a bump-in-the-wire L2 bridge); standardized on **nftables NFQUEUE inline**, which is what the spec's own pipeline, the per-flow "policy attached" semantics, and the `inline_drop`/`inline_tap` modes actually require; and (2) a **generated nftables example that matched WireGuard on `wg0`** (WireGuard transport packets arrive on the physical WAN iface with UDP/51820 — `wg0` carries only decapsulated traffic). A cluster of smaller accuracy fixes (Kea control-socket commands, nonexistent `suricata-update --dry-run` and `swanctl --dry-run`, `tcp option mss set` syntax, XDP driver support/Realtek, TPROXY mechanics, missing OpenVPN generator row, wrong seed interface count, WireGuard auth honesty, `vpn:status` event list drift) were fixed in place. AUTH_AND_RBAC.md needed **no changes** — the 8-role matrix matches the spec's role list, with a justified, documented divergence on the spec's `viewer` default.

Severity totals: **CRITICAL 0 · MAJOR 7 · MINOR 15** (23 issues, all fixed or verified).

## (b) Issues found (numbered, with severity, file, section, what was wrong, fix applied)

1. **MAJOR — DATA_PLANE.md §1/§2/§8 — Suricata inline mode contradiction.** Diagrams and the per-stage contract placed Suricata *inside* the routed path (after nftables/NAT/TPROXY/nDPI, before tc) while claiming "AF_PACKET v3 now, AF_XDP future" and "AF_PACKET fanout". AF_PACKET inline is a bump-in-the-wire interface pair that bypasses the host stack — it cannot sit between NAT and tc, and it cannot enforce per-flow "policy attached" selection. Fixed: standardized on **NFQUEUE inline** (`queue num 1-4 fanout bypass` emitted by the generator; Suricata nfq mode, one worker per queue; drop verdict = `inline_drop`, accept+alert = `inline_tap`; `bypass` flag = fail-open), with AF_PACKET reserved for the passive/tap capture role and AF_XDP kept as the future 10 Gbps ingestion path. Added an explicit Architect note; flagged for spec/ADR reconciliation (see (c)).
2. **MAJOR — DATA_PLANE.md §2.2 ruleset sketch — WireGuard matched on the wrong interface.** `iifname "wg0" udp dport 51820 accept` — WireGuard transport arrives on the physical WAN interface; `wg0` only ever carries decapsulated IP packets, so this rule would silently break handshakes and teach the generator wrong input-chain logic. Fixed to `iifname "wan0" udp dport 51820 accept` with a comment explaining `wg0` carries already-decapsulated traffic.
3. **MAJOR — DATA_PLANE.md §2 stage table — nDPI described as a standalone "daemon".** nDPI is a library; the spec only says "helper to Suricata or standalone" without a host process. A future agent could scaffold a fake `ndpi` daemon. Fixed: row and §3 now state nDPI runs **inside the Go flow-classifier worker (libndpi via cgo)**, which publishes the ~300-protocol app catalog, populates nftables app sets, and enriches Suricata metadata; failure mode re-worded to "worker down". ARCHITECTURE.md §2 node label annotated "(library in Go flow worker)".
4. **MAJOR — CONTROL_PLANE.md §2 — generator contract named commands that don't exist.** Kea: `keactrl reload`/`keactrl config-test` (keactrl only supports start/stop/restart/status/version — validation/apply actually go through the Kea control-socket commands `config-test`/`config-reload`); Suricata: `suricata-update --dry-run` (no such flag — rule testing is `suricata -T`, which suricata-update runs automatically); StrongSwan: `swanctl --load-conns --dry-run` (swanctl has no dry-run). ## (d) Residual risks / open questions

1. **Suricata 5+ Gbps inline with the full ET ruleset remains optimistic** even on the 8C/16T Performance tier; docs now hedge with hardware-tier caveats, but marketing material should not quote the 5 Gbps figure without the tier qualifier.
2. **NFQUEUE throughput ceiling:** a single `queue num` range fanout scales across cores, but re-injection (verdict → kernel) costs more than AF_PACKET fanout on very high pps. If 10 Gbps IPS becomes a hard requirement, the AF_XDP ingestion path (already listed as future) plus measured benchmarks must precede any SLA commitment.
3. **`bypass` fail-open default is a security posture decision**, not just an engineering one: if Suricata dies, WAN-side `inline_drop` policies currently fall open (queue bypass) unless the operator chooses fail-close. Recommend a product decision + an `alerts:new` notification when the engine is down (no doc currently requires that alert).
4. **WireGuard remote access has no per-user revocation** short of removing the peer (key persists on the client). Phase 2 should add peer expiry/rotation UI; flagged honestly in M05 §1 now, but the risk stands for Phase 1 deployments.
5. **Multi-WAN `load_balance` weighted split needs definition** of hash granularity vs `weight` percentages (nftables `numgen` modulo weights per connection). M02 now says "per-connection flow hashing"; the exact mapping (weight → modulo bands) is left to the generator spec.
6. **HA conntrackd sync with NFQUEUE/Suricata:** spec Phase 1 includes conntrackd, but IPS state does not sync (spec cuts IPS state sync to Phase 3) — after failover, in-flight IPS inspections restart cold. Docs mention conntrackd but not this consequence; consider a one-line note in the HA module doc (M10/HA owner).
7. **TPROXY + hairpin/DNAT interplay** (Phase 2): a DNAT'd port-forward flow that also matches a proxy policy will hit TPROXY before the DNAT decision is visible; the generator must exclude DNAT destinations from transparent-proxy selection. Noted here for the Phase 2 proxy design; no Phase 1 impact.
8. **Concurrent-edit hazard:** sibling review 2C touched the same files during this pass. All conflicts observed were complementary; a final grep for `AF_PACKET`, `keactrl`, and `wg0.*51820` after all reviews land is cheap insurance.
